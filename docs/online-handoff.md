## Архитектура: вариант B, «хост-игрок»
Браузер хоста считает весь мир (воксели, враги, боссы, снаряды). Гость шлёт только ввод и получает снимки мира, рисует их у себя. Сервера с игровой логикой нет.

## Принятые решения
| Вопрос | Решение |
|---|---|
| Соединение | WebRTC напрямую между браузерами; сервер нужен только для сигналинга (первичного обмена). Запасной ретранслятор — не в первом этапе, но интерфейс транспорта делать заменяемым |
| Вход в комнату | Короткий код (4–5 символов): хост видит код, друг вводит его в меню |
| Игроки и режимы | Первый этап: 2 игрока, только кооператив (PvE). PvP и больше игроков — потом |
| Выход хоста / обрыв | Игра заканчивается: гость видит «хост отключился» и возвращается в меню. Передачу хоста не делаем |

## План работ (по порядку)
1. **Состояние вместо общих `let`.** Листья без общего состояния → симуляция (воксели, враги, боссы). Порядок в разделе «Модули» в `CLAUDE.md`. После каждого шага `npm test` зелёный.
2. **Транспорт.** Тонкий слой `send/onMessage/connect(code)` над WebRTC DataChannel; сигналинг через публичный сервис (выбрать и записать сюда). Интерфейс не зависит от реализации.
3. **Лобби.** Создать комнату (код), войти по коду, готовность, старт.
4. **Снимки и ввод.** Гость: ввод (стик, огонь, способности) с номером тика → хост. Хост: снимки в ~10–20 Гц (танки, враги, боссы, снаряды, разрушения вокселей как события, а не весь мир), гость интерполирует.
5. **Второй танк у хоста.** Цели врагов, захват, x-ray, HUD, респавн и задания учитывают двух игроков.
6. **Тесты.** `tests/net/README.md` (два клиента в харнессе): подключение по коду, ввод доходит, снимок сходится, обрыв хоста даёт выход в меню.

## Решения второго чата (v28.0)
- **Сигналинг:** публичное PeerJS-облако. Недоступно → сообщение «Сервер комнат недоступен».
- **WebRTC не соединился:** вариант А — через 10 с текст «попробуй другую сеть, например Wi-Fi». Запасной ретранслятор добавим, если у вас с другом будут реальные обрывы.
- **Масштаб на двоих:** HP врагов без изменений, число врагов ×1.5; лом делится 60/40 в пользу того, кто подобрал; задание засчитывается, когда его выполнил любой из двоих.
- **Объём первого этапа:** одна арена и один босс, остальное подключаем по списку. Решено: **Свалка (`junk`) и Крот**. Старт онлайна — `NET_START` в `src/game/41-lobby.js`. Крот появляется только при активном задании `krot` (`MS.i`), поэтому хост должен выставлять его при старте — делаем вместе со снимками (шаг 4), чтобы не трогать сохранение игрока раньше времени.
- **Сделано:** шаги 2 и 3 плана (транспорт, лобби) и тесты к ним (v28.0); в шаге 1 — утилиты, звук, частицы (v28.1, механизм описан в `CLAUDE.md`, «Модули»). Дальше — симуляция: воксели (02), потом враги и боссы; затем шаг 4 (снимки и ввод).

## Открытые вопросы
- Как гость видит разрушаемые воксели: события, а не полные снимки (детали при шаге 4).
- Как хост запускает задание Крота, не портя прогресс сохранения (шаг 4).

## Не забывать
- Правила кода из `CLAUDE.md` (зарезервированные поля врагов, флаги, никаких `new Vector3` в кадре).
- Тестировать реальными снарядами; сетевую часть — двумя клиентами.
- Релиз по навыку `sharotank-autotest`: lint → `npm test` → версия → `docs/design-history.md` → коммит `vX.Y: …` → push.
