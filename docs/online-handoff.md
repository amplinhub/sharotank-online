## Главная переделка: второй танк (нужна и PvE, и PvP)
Сейчас танк игрока один: объект `TK` (1226 обращений в 37 файлах) и модель `tank` (`14-tank-physics.js`). Враги целятся в `TK`, камера и HUD смотрят на `TK`, урон идёт в `TK.hp`.
Как переводить, не ломая одиночку:
1. Завести массив `SHT.tanks = [TK]` и `SHT.me` (индекс своего танка). Одиночная игра = массив из одного танка, поэтому все тесты обязаны оставаться зелёными на каждом шаге.
2. Разделить обращения на три вида и чинить по одному виду за раз:
   - **«мой танк»** (камера, HUD, ввод, звук мотора, x-ray вокруг игрока, гараж, сохранение) — остаются на `TK`, где `TK = tanks[me]`;
   - **«любой танк»** (цели врагов, восприятие, захват, урон от взрывов, давка людей, подбор лома, круги заданий, вход в зону перехода) — циклом по `tanks` или через `nearestTank(x,z)`;
   - **«физика танка»** (`14`, `15`, `37`, `42`) — функции, которые принимают танк параметром, а не читают глобальный `TK`.
3. Модель второго танка: `makeTank(false, upgrades)` уже умеет строить любую машину, нужна только вторая копия с цветной меткой игрока.
4. Порядок файлов: 14 физика → 15 оружие → 22/23/45 враги и ИИ → 32–36 боссы → 24/50 задания → 19 камера/HUD. После каждого — `npm test`.
Объём: самый большой кусок всего онлайна, несколько чатов.

## Этап 0. Свой сервер (сейчас)
1. На VPS: `curl -fsSL https://raw.githubusercontent.com/amplinhub/sharotank-online/main/server/install.sh | bash` (или `… | bash -s -- свой.домен`). В конце — «ГОТОВО» и адрес.
2. Проверить адрес в браузере телефона по Wi-Fi и по мобильному: короткий JSON «PeerJS Server».
3. Проверить игру без пересборки: Pages-ссылка + `?sig=АДРЕС` на двух устройствах.
4. Работает → адрес в `src/net/config.js` (`SIGNALING.host`), релиз.
5. **TURN-ретранслятор на том же VPS (coturn).** Без него часть пар «мобильный ↔ Wi-Fi» не соединится напрямую (ошибка «timeout» после того, как код принят). Добавить сервис `coturn` в `server/docker-compose.yml` (порты 3478 udp/tcp и диапазон для relay), логин/пароль в `.env`, `iceServers` в `config.js`. Делать, если тест п.3 даёт «timeout» между разными сетями.

## Этап 1. Кооператив (PvE) — по шагам
1. **Протокол** (`src/net/proto.js`, настоящий модуль):
   - гость → хост, ~30 раз/с: `{t:'in', n, mv:[x,z], aim:[x,z,dist], fire, wpn, abil, kit}` — ровно то, что сейчас дают стики/клавиатура;
   - хост → гость, ~15 раз/с, ненадёжно: снимок — оба танка (x,z,h,башня,hp,оружие), враги в радиусе 60 м (id, тип, x,z,rot, hp, state, флаги), босс, снаряды;
   - хост → гость, надёжно: события — `explode`, появление/смерть врага, лом, люди, ход задания, радио, конец боя.
2. **Воксели событиями, не снимками.** Гость сам повторяет `explode(px,py,pz,r,power,…)` с тем же `seed`. Для этого в разрушении (`11`, `02`) `rnd` (сейчас `Math.random`) заменить на ГПСЧ с зерном из события. Раз в несколько секунд — хеш чанков вокруг игроков; не сошлось → хост шлёт эти чанки целиком.
3. **Гость — «тонкий»:** у гостя не крутятся ИИ врагов, боссы, спавны, задания. Он рисует то, что пришло, плавно интерполирует (задержка ~100 мс), свой танк двигает сам и сверяет с хостом (мягкая поправка, если расхождение > 0.5 м).
4. **Второй танк у хоста** — см. «Главная переделка».
5. **Старт без порчи сохранения:** хост запускает «онлайн-задание» (копию нужного задания со своим id, например `net-krot`), его итог не меняет `MS.i` и прогресс кампании; награда — только лом и медали обоим.
6. **Правила кооператива:** урон роботов по игрокам ×2; огонь по своим включён (свои снаряды и взрывы ранят союзника; «РСЗО» и артудар тоже). Лом 60/40, задание засчитывается всем.
   - **Враги волной:** на старте врагов района ×1.15 (не намного больше обычного). Когда враг умирает, в очередь встаёт новый; он появляется в точке вне видимости **всех** игроков (дальше ~35 м и без прямой линии до любого танка, `navOk`), пока общий счёт не дойдёт до ×1.5. Одновременно живых не больше обычного ×1.2.
   - **Подбит:** танк не взрывается насовсем, а встаёт «обломком» с дымом и маяком на HUD у союзников. Союзник подъезжает ближе 4 м и стоит 3 с (полоса над танком) → друг поднимается с 30 % брони. Проигрыш — подбиты все одновременно. Ремонт R по своему танку как обычно.
7. **Тесты:** два клиента в харнессе: ввод гостя двигает его танк у хоста; снимок совпадает; гость стреляет реальным снарядом → враг у хоста теряет HP; взрыв даёт одинаковый хеш чанка у обоих; обрыв хоста → меню.
8. Дальше по списку: другие арены → районы → задания-сюжет (защиты, эвакуации) → все боссы.

## Этап 2. PvP — после рабочего кооператива
Предлагаемые правила (пользователь утверждает):
- **Режим «Дуэль»** на арене: 1×1, до 5 побед или 5 минут. Респавн через 3 с на своей базе (`ARENA.bases` уже симметричны), ящики боеприпасов на `ARENA.pads`. Врагов нет.
- **Режим «Флаг»** позже: свой флаг на базе, довезти чужой (механика `flag` из заданий уже есть).
- **Танки:** равные условия — все на одной машине с одинаковыми улучшениями (например 5T-L, улучшения уровня 2; выбор танка из списка, где у всех одинаковые числа, — позже). Свои прокачки и наборы поддержки в PvP не действуют.
- **Обзор 90°:** конус по направлению башни. Вне конуса экран слегка затемнён (полупрозрачный сектор-маска поверх сцены, шейдер или плоскость под камерой), противники вне конуса и за стенами не рисуются (у гостя хост даже не присылает их в снимке — нечестно не подсмотреть). Звук выстрелов слышен всегда, со стороны.
- **Без автонаведения:** выключить автозахват, «ближайшую цель» правого стика, автоповорот башни по ходу и ручной захват средней кнопкой; ракеты летят по прямой/в точку прицела, без самонаведения на танк.
- **Урон танк-по-танку:** снаряды уже бьют по боку/корме роботов; для танков те же зоны брони (лоб ×0.7, борт ×1, корма ×1.3) и щит «Крепости». Маскировка «Тени» видна противнику ближе 15 м. Таран по танку — урон по формуле удара.
- **Разрушения:** арена ломается как обычно (события, как в PvE) — это главная фишка.
- **Честность:** хост считает попадания, значит, хост может жульничать — для игры с друзьями это приемлемо. Для «серьёзного» PvP со случайными людьми нужен свой игровой сервер (симуляция на VPS на Node без рендера) — возможно после того, как симуляция переедет в модули `src/lib/`.
- **Задержка гостя:** гость видит мир на ~100 мс позже, поэтому хосту чуть выгоднее. Смягчение: попадания гостя хост проверяет «назад во времени» на 100–150 мс (хранить историю позиций танков 0.5 с).
- **Тесты:** дуэль двумя клиентами: попадание снарядом гостя по хосту отнимает HP, респавн, счёт раунда, конец матча.
