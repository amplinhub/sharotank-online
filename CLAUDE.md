# Шаротанк Онлайн — правила для Claude

Воксельная танковая игра на Three.js r128. Сейчас одиночная (v27.4), цель — кооператив и PvP с друзьями
по схеме **хост-игрок** (вариант B: браузер хоста считает мир, гости шлют ввод и получают снимки).
История версий и спецификация механик — `docs/design-history.md` (числа и поведение оттуда — эталон).

Общение с пользователем: по-русски, коротко, неформально. На крупных задачах сначала 2–4 уточняющих вопроса.

## Команды
| | |
|---|---|
| `npm run dev` | dev-сервер Vite (полная перезагрузка при правке `src/game/`) |
| `npm run build` | `dist/` (GitHub Pages) + `dist-single/index.html` (один файл: локальная версия и артефакт Claude) |
| `npm run lint` | ESLint по склеенной игре (`tools/lint-game.mjs`) + тесты/инструменты. Ошибок должно быть 0 |
| `npm test` | сборка + все автотесты в headless Chromium. `-- --quick` пропускает медленные, `-- --only=20` один набор |

## Устройство
- `index.html` — разметка HUD/меню. **Шапка `<!doctype html>` + `<meta name="viewport" …>` обязательна** (без неё на телефоне UI крошечный — v27).
- `src/styles.css`, `src/three-global.js` (three@0.128 из npm → `window.THREE`, без CDN), `src/main.js`.
- `src/game/NN-имя.js` — код игры. **Это пока одна общая область видимости**: `tools/vite-game-concat.js` склеивает файлы по номеру в один ES-модуль (с source map). Порядок важен: объявление должно стоять в файле с меньшим номером, чем код, который выполняется при загрузке.
- Карта: 00 утилиты · 01 палитры · 02 воксели · 03–05 локации/арены · 06–09 рендер, земля, частицы, луч · 10–12 экономия, разрушение, машины · 13–15 танк, физика, оружие · 16 звук · 17 гараж · 18–21 ввод, камера/HUD, качество, загрузка локаций · 22–23 враги · 24 задания · 25 x-ray/навигация · 26–31 визуал заданий, детали мира, LOD, лагерь, поддержка, системы мира · 32–36 боссы (ядро, Крот, Шершень, Энергобот, Дракон) · 37–39 способности, «Тень», броня · 40 главный цикл и `window.__dbg`.
- `tests/` — харнесс (`harness.mjs`, многоклиентский), наборы `tests/suites/NN-*.mjs`, план сетевых тестов `tests/net/README.md`.
- CI: `.github/workflows/ci.yml` — lint → build → test, при push в `main` деплой `dist/` на GitHub Pages.

## Правила кода (выучены на ошибках)
1. **Зарезервированные поля врагов.** Код попаданий (`15-weapons.js`) ветвится по `eh.gd / eh.shd / eh.bee / eh.rd / eh.civ`, `eRemove` убирает `e.halo / e.pool`. Враг/босс не должен заводить поля с этими именами (Крот с `e.rd` «умирал» от первого снаряда — v27.3). Проверяет тест `00-static`.
2. Семантические флаги врага: `state==='fly'` — не попадают снаряды и захват; `inv` — неуязвим (`armFx`); `lockable`; `noCol` — без столкновений с танком/врагами; `xhide` — без x-ray круга и тени; `boss`; `fromBoss` — умрёт вместе с боссом; `xf` — трансформатор (не считается в «осталось врагов»); `onHit(e,dmg,dx,dz,src)` — хук попадания; `xrR` — радиус x-ray круга.
3. `mergeStatic` сливает только прямые меши группы; всё анимируемое — `userData.keep=true`.
4. В кадре: никаких `new Vector3/Color` (временные `_bw`, `_bw2` и т.п.), DOM пишем только при изменении значения, `updateMatrixWorld(true)` у больших моделей — через `wmOnce(e)`.
5. Исключение в `update` врага или в `later()` ловится и логируется (`enemyCrash`) — тесты считают `console.error` провалом.
6. Боссы: фазы без текста (`bossPhase` молчит), смерть только через `bossDeath(...)` (взрыв + разлёт модели + `bossWin`), миньоны помечаются `fromBoss`.
7. Навигация: `navR` ≈ реальный радиус (иначе застревает у кранов); у ходячих боссов — детектор застревания с объездом.
8. Числа баланса — догадки; пользователь проверяет на телефоне и просит подкрутить.
9. Тестировать реальными снарядами (`shellAt` в харнессе) — синтетический `enemyHit` не ловит баги ветвления в коде попаданий.

## Тесты и релиз (навык `sharotank-autotest`)
lint 0 ошибок → `npm test` зелёный → bump `version` в package.json → раздел в `docs/design-history.md` → коммит `vX.Y: …` → push (CI задеплоит Pages) → артефакт Claude из `dist-single/index.html` → пользователю: файл + что проверено / что нет.

## Модули: план миграции
Склейка — промежуточный шаг. Чтобы файл стал настоящим ES-модулем, его общие `let` переезжают в объект состояния (`G.transit`, `G.LOC`…), затем добавляются `export/import`. Порядок: сначала листья без общего состояния (00 утилиты, 08 частицы, 16 звук), потом симуляция (воксели, враги, боссы) — её же будет крутить хост в онлайне — и только потом рендер/HUD.
